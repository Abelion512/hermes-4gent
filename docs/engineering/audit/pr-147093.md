## 1. Human Specification

### Problem
> "The Bitwarden login backend reads `bw`'s local cache, which only `bw sync` refreshes. Hermes never runs it, so a login added or shared into the vault after `bw login` (for example, into a collection the agent's account can see) never reaches `browser_vault` until the user runs `bw sync` by hand."

### Proposed Solution
> "This PR makes the backend sync on demand: on unlock, on a stale listing, and once on a missing handle. There's no polling and no background thread."

### Acceptance Criteria
- [x] Sync after unlock — `bw sync` runs once right after successful unlock
- [x] Sync on listing — `list_items()` syncs when last sync older than `sync_on_list_seconds` (default 60)
- [x] Sync on miss — `get_meta()` for unknown handle syncs once more (debounced 5s) and retries
- [x] Non-fatal failures — failed sync logs warning, falls back to cached items
- [x] Config — `vault.bitwarden.sync_on_list_seconds: 60` (0 disables)
- [x] Security — `BW_SESSION` goes only to the one child process, never Hermes env
